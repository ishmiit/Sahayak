## Decisions taken while building

Defaults chosen so the build can move; the team can overturn any of them.

| # | Decision | Why | Revisit |
| --- | --- | --- | --- |
| D1 | Dev LLM is `qwen2.5:3b` via Ollama, behind a backend interface that also speaks the OpenAI-style API (llama.cpp server, or Crucible if it exposes the same API) | Already installed on the dev laptop (i5-10210U, 7.8 GB RAM, no GPU); a 14B model cannot run here | Model bake-off (PRD open decision). Qwen2.5-3B's licence is research-only, so it is a dev default, not the shipped model |
| D2 | Python 3.10 + FastAPI node server; vanilla JS phone app with no build step | Keeps the app under 2 MB, works offline, no node_modules | — |
| D3 | Models and runtime data live in `%USERPROFILE%\.sahayak`, outside OneDrive | Avoids syncing gigabytes | — |
| D4 | Signals and classifier decide the verdict; the LLM only explains and may raise, never lower, a verdict | Matches PRD safety design; system works with the LLM off | — |
| D5 | Ollama's update checker contacts the internet, so the demo node must block it (firewall) or run llama.cpp server | Zero-egress claim | Phase 6 |
| D6 | Model explanations are enabled only for languages the model has been cleared for (`SAHAYAK_LLM_LANGS`, default `en`). Hindi uses the vetted templates | `qwen2.5:3b` writes fluent-looking but meaningless Hindi; the script check cannot catch that | Turn Hindi on after a model passes a Hindi quality check (bake-off) |
| D7 | The explanation arrives after the verdict (`/api/check` returns in milliseconds; `/api/explain` follows) | The verdict never waits for the model; a slow CPU only delays the extra sentence | — |
| D8 | The Navigator uses no model at all: rules, amounts and sentences all come from the schemes pack | Eligibility and amounts must never be invented; templates are already bilingual | Add model phrasing only behind the safety gate's rupee check |
| D9 | BPL status is read from the ration card (AAY or BPL/PHH = likely, APL = no, none = unknown); PM-JAY below 70 is always "check the list" | The app cannot see BPL or SECC lists; "likely" and "check" say so honestly | A state overlay can map its own card types |
| D10 | 12 schemes, not 10: e-Shram and PM-SYM are separate entries (different rules), and Jan Dhan is added because PMSBY, PMJJBY and APY need a bank account | One PRD row held two schemes with different ages and income tests | — |
| D11 | The interview decides relevance on everything the person will see, including "after you open a bank account" | A 5,000-case sweep showed that judging on eligibility alone skipped the tax question and changed 51 results; fixed and now checked exhaustively | — |
| D12 | Speech out uses Piper voices (Hindi priyamvada and pratham, English lessac) run by sherpa-onnx | Fast on a laptop CPU (about half real time), offline, Apache-2.0 runtime. The Hindi voices are licensed CC BY-NC-SA (non-commercial) and under IIT-Madras terms: fine for this prototype only | Indic Parler-TTS (Apache-2.0, the PRD's first choice) for a pilot; too slow on this CPU for live use |
| D13 | Speech in uses Vosk small Hindi (42 MB, Apache-2.0) | 0.23x real time on the dev laptop, 15.4% WER on FLEURS Hindi, and grammars for short answers | IndicConformer bake-off (the PRD's first choice) not run yet; English recognition is weak (Vosk reports 49% WER on lectures) and is secondary |
| D14 | Where the browser will not open the mic (plain HTTP), the app uses the phone's recorder app instead | Phone browsers open the mic only on HTTPS or localhost; HTTPS needs a domain the team has to buy | Drop the fallback once HTTPS is set up |
| D15 | Firewall scripts are written but not run on the dev laptop | They cut the machine's internet; they are for the demo node | Run on the demo node (team) |
| D16 | The pack-signing key lives in `%USERPROFILE%\.sahayak\keys`; `scripts/packtool.py` re-signs on save | An edited pack with a stale signature is refused by design | Share the key with Roshan out of band |
| D17 | The case log keeps no optional name or number fields at all, and the queue keeps the verdict, not the message | Simplest way to meet "names and numbers optional and off by default"; the person is at the counter anyway | Add opt-in fields only if an operator needs them |
| D18 | The screenshot reader joins lines the screen wrapped (same left edge, no gap) into one paragraph before checking; the checker's sentence rules stay as they are | A genuine SBI OTP screenshot wrapped as "Never / share it with anyone" read as an OTP request (a false alarm); typed messages keep their own line breaks | — |
| D19 | Text is folded before checking so disguises read as the plain word: digits between letters read as letters ("bl0cked"), and written-out links ("hxxp://", "[.]", "dot xyz") are undone; never inside a link, a code, a masked number or an amount. Two red-team genuine messages stay flagged on purpose: a short link, and a debit alert asking you to call or SMS a mobile number | Red team v0 found these evasions; flagging a hidden link destination or a mobile callback number is safer than trusting a header that can be spoofed | — |
| D20 | The explanation model is off by default (`SAHAYAK_LLM=none`); the vetted templates explain every verdict in Hindi and English | On the laptop qwen2.5:3b took 11–21 s and its English lines were often garbled or wrong ("IpaPost-Courier", "no phone number given", "Call from phone number not recognized" for a harmless text) though they passed the gate; a smaller model raised a genuine OTP to Suspicious | Re-test with a larger model on a 16 GB node; `SAHAYAK_LLM=llamacpp` turns it on |
| D21 | Pack signatures and pack hashes cover the file with line endings as LF (`signing.canonical`); signatures made before 6 Oct over CRLF bytes still verify | The packs were signed on Windows over CRLF bytes, git stores them as LF, so every signature failed on a macOS or Linux clone and the node refused all six packs (found on a fresh clone, 6 Oct). In a JSON pack a raw line break only sits between tokens, so this cannot change what a pack says; any other edit still fails (`tests/test_node.py`) | Re-sign with `python scripts/sign_packs.py` at the next pack change; the CRLF fallback can then go |
| D22 | The collect-request trick ("approve the request to reverse it", "sent by mistake, accept the request and return it", Hinglish and Hindi word order too) fires `upi_receive`; the UPI-receive patterns and `refund_bait` now skip warning sentences | sb-0109 (logged 2 Oct) and the common "sent by mistake" scam were missed; warnings from banks and NPCI about refund and collect-request scams were themselves called Scam. Code only, no pack change: 356 benchmark messages give the same verdict as before except sb-0109, now caught | — |
| D23 | `vosk>=0.3.44` instead of `>=0.3.45` | 0.3.45 has no wheel for Apple Silicon Macs, so `pip install -r requirements.txt` failed there; 0.3.44 has the same API (voice tests pass on macOS) | — |

## How to run

```powershell
# from the sahayak folder; uses the global Python 3.10 on the dev laptop
python -m pip install -r requirements.txt
python -m sahayak                 # node on http://0.0.0.0:8000 ; phones on the same Wi-Fi open http://<laptop-ip>:8000
python -m pytest                  # 189 tests, ~1 min (voice tests use the installed models)
python bench/build_schemebench.py # 200 personas + expected answers from the independent oracle
python bench/eval_schemebench.py --report              # rules, interview length, sweep, amount trace
python bench/eval_schemebench.py --exhaustive --report # adds every answer combination (~15 min)
python bench/build_scambench.py   # rebuild ScamBench from the source files
python bench/train_models.py      # pattern pack + classifier (train split; thresholds on dev)
python bench/eval_scambench.py --split dev            # tune on dev only
python bench/eval_scambench.py --split test --report  # frozen test number + markdown report
python scripts/screenshots.py     # 12 phone-size screenshots into docs/screenshots (needs Playwright)
python scripts/get_models.py      # once, with internet: offline speech models into %USERPROFILE%\.sahayak\models
python scripts/build_speech_cache.py                   # pre-synthesise every fixed sentence (~30 min, CPU)
python bench/eval_voicebench.py --fleurs --report      # Hindi recognition on Google FLEURS (public reference)
python bench/eval_voicebench.py --report               # the team's VoiceBench recordings
python bench/voice_latency.py --report                 # mic release -> first audio (node running)
$env:SAHAYAK_VOICEBENCH = "1"; python -m sahayak       # recording mode for VoiceBench: /app/voicebench.html
```

Settings (environment variables): `SAHAYAK_LLM` = `ollama` | `openai` | `none`; `SAHAYAK_LLM_URL`; `SAHAYAK_LLM_MODEL` (default `qwen2.5:3b`);
`SAHAYAK_LLM_LANGS` (default `en`); `SAHAYAK_PORT` (default 8000); `SAHAYAK_HOME` (default `%USERPROFILE%\.sahayak`).
